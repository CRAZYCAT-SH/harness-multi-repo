# 短命 PR 合并策略

本文档描述 harness-demo-fullstack 项目的 PR 合并哲学与门禁策略。

## 核心哲学

**修正便宜，等待昂贵。**

目标：PR 从开启到合并不超过 24 小时。长期存活的分支是集成风险的温床，短命 PR 通过频繁小批量合并降低冲突概率与认知负担。

## 最小合并门禁

PR 合并前必须通过以下检查（全部阻塞性）：

1. **类型检查** — `pnpm typecheck`
2. **架构 Linter** — `pnpm lint:arch`
3. **单元与集成测试** — `pnpm test`

以下检查为非阻塞性（仅报告）：

- **端到端测试** — `pnpm test:e2e`（结果以报告形式呈现，不阻塞合并）

## Flaky 测试处理

| 场景 | 处理方式 |
|------|----------|
| 测试首次失败 | 自动重试，最多 2 次（共 3 次尝试） |
| 3 次全部失败 | 标记为失败，阻塞合并 |
| 3 次中至少 1 次通过 | 标记为 flaky，写入 `docs/generated/flaky-tests.md`，不阻塞合并 |

## 实践建议

- 每个 PR 聚焦单一变更目的（一个功能、一个修复、一次重构）
- 避免"顺手"修改不相关代码
- PR 描述包含：变更摘要、测试验证方式、受影响的业务域
- 合并后自动运行 `pnpm quality:score` 更新质量评分
